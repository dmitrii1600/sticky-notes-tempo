# Sticky Notes

A single-page sticky notes board built with React 19 and TypeScript. No UI
libraries, no state management libraries - the only runtime dependencies are
`react` and `react-dom`.

## Running it

Requires Node 20 or newer.

```
npm install
npm run dev
```

The dev server prints a local URL (http://localhost:5173 by default).

To produce a production build and serve it locally:

```
npm run build
npm run preview
```

`npm run build` type-checks the project (`tsc -b`) before bundling, so a type
error fails the build.

## Using the board

- **Create**: drag out a rectangle anywhere on empty board - the note is created
  at that position with that size. A plain click drops a default-sized note.
- **Move**: drag a note by its coloured top bar.
- **Resize**: drag the grip in the bottom-right corner.
- **Delete**: drag a note onto the trash zone in the bottom-right, or use the
  `×` button that appears on the note when you hover it.
- **Edit**: the body of a note is a text area, just click and type.
- **Colour**: the toolbar picks the colour of the next note; the swatches on a
  note's top bar recolour it.
- Clicking a note brings it to the front, and the board is restored from local
  storage on reload.

## Architecture

The domain lives in `src/notes` and knows nothing about React. `types.ts`
describes a note (a branded `NoteId`, a rect, a colour, text and a z-index),
`geometry.ts` holds every rule about where a note may be - clamping into the
board, the minimum size, hit testing - and `reducer.ts` is a single reducer over
a discriminated union of actions. The board size is part of the reducer state,
which is what lets the reducer, rather than the components, own the invariant
that a note is always inside the board: moving, resizing, creating and reacting
to a window resize all go through the same two functions in `geometry.ts`. Ids
are generated by the action creators in `NotesContext.tsx` so the reducer stays
pure. Persistence is a debounced write to local storage, and anything read back
is validated field by field before it is trusted - a stale or hand-edited entry
should not be able to crash the render.

All three drag interactions - creating, moving and resizing - are the same
gesture with different callbacks, so they share one hook, `usePointerDrag`. It
takes a pointerdown, captures the pointer so the gesture survives the cursor
outrunning the element or leaving the window, listens on `window` for the rest
of the gesture (which also covers `pointercancel`), and coalesces moves with
`requestAnimationFrame` so a callback runs at most once per frame. The hook
works in client coordinates and knows nothing about the board: moving and
resizing only need the delta, and the board converts to its own coordinates
where it has to. The trash zone follows the same split - the board owns the zone
and does the hit testing, a dragged note only reports where the pointer is.

The rendering strategy is built around not touching the store during a gesture.
A note being dragged previews itself from local state and dispatches exactly one
action on release, so a drag costs one store update rather than one per frame,
and movement is applied as a CSS `transform` to keep it off the layout path.
`StickyNote` is memoised and receives everything through props - the board is
the only component that reads the notes context - so typing in one note or
rubber-banding a new one does not re-render the rest of the board.

## Trade-offs

Things left out deliberately, given the time budget:

- No tests. The reducer and `geometry.ts` are pure and were written to be easy
  to test; that is where I would start.
- Notes are stored in an array. For hundreds of notes a keyed map plus an
  explicit z-order list would be a better fit, but at this scale the array keeps
  the reducer readable.
- Local storage only. The persistence layer is a single module with a
  load/save pair, so swapping it for an async REST client is a contained change.
- Mouse and pen only, by design - the task targets desktop. Pointer events mean
  touch would mostly work already, but it is not something I tested.
